## 1. 질문

이 런으로 사진을 다 찍었는데, 각 source_point에서 변위측정센서(Keyence standoff 루프)가
툴을 얼마나 이동(보정)했는지를 소스포인트별로 정리해 달라.

## 2. 데이터 출처와 방법

- Ra map: `log/apriltag_nav/ra_maps/<런>.csv` — `execution_message` 열에 점별 결과
  요약 (`standoff ok (err +0.01 mm, 2 steps, travel 4.0 mm)` 등). 여기의 `travel`은
  이동 거리의 절대값 합이라 순 보정량이 아니다.
- arm_node 로그: `log/ros/0eee4cc4-c917-11f1-a7d6-29421ab6021d/arm_node-3.log`
  (13:32–15:11 구간). 점마다 `[Standoff n/N] err … -> approach|retreat … mm` 줄이
  이동 하나당 하나씩 있고, 그 뒤 `[Scan] Point <point_id>` 줄이 따른다.
- 방법: 로그를 순서대로 읽어 `Execute scan point` 블록마다 이동 목록을 모으고,
  `[Scan] Point` 의 point_id 로 Ra map 행(validated_at 순)과 1:1 결합. 1192개 모두
  point_id 가 일치함을 확인. 순 보정량 = Σ approach − Σ retreat.

## 3. CSV 열

| 열 | 뜻 |
|---|---|
| `group_id`, `point_id`, `source_point_id` | Ra map 과 같음 (point_id = 경로 행, source_point_id = 작업점) |
| `time` | 그 점의 standoff 시작 시각 |
| `status` | `ok` / `out of range on the far side (seek disabled)` / `not converged …` / `no valid reading …` / `no Keyence data …` / `live guard …` |
| `first_err_mm` | 도착 직후 센서가 읽은 오차. **음수 = 표면에서 너무 멀다** |
| `net_move_mm` | 센서 보정으로 툴이 실제 이동한 순 거리. **양수 = 표면 쪽으로 접근**, 음수 = 후퇴. "얼마나 보정했는가"는 이 값 |
| `n_moves` | 이동 횟수 |
| `travel_mm` | 이동 거리 절대값 합 (후퇴 포함, Ra map 의 travel 과 같음) |
| `final_err_mm` | 마지막 측정 오차 |
| `guard_stops` | 라이브 가드가 이동을 멈춘 횟수 |
| `moves` | 각 이동을 순서대로, 부호 포함 (예 `+3.758 +0.254`) |
| `x`, `y`, `z` | Ra map 의 world 좌표 |
