## 0. 한 줄 요약

인쇄된 A0 AprilTag 시트를 **치수를 아는 강체 기준물(ground truth)** 로 사용합니다. 두 카메라가 같은 시트를 동시에 관측할 때 생기는 **닫힌 변환 루프**를 이용해 다음 두 고정 외부 파라미터를 추정합니다.

- `팔베이스 → front_cam` ($X$)
- `엔드이펙터 → hand_cam` ($Y$)

추정 결과는 URDF 또는 TF의 static transform에 **보정값으로 반영**합니다.

## 1. 배경과 목적

### 1.1 연구 맥락
- 사용자: 로보틱스 석사과정. MADRL과 sim-to-real 연구를 하며, Isaac Sim/Lab과 ROS2를 사용합니다.
- 대상: 모바일 베이스에 매니퓰레이터(FR5 계열 협동로봇)를 올린 **모바일 매니퓰레이터**
  - `front_cam`: 모바일 베이스 전면에 **지면을 수직으로 내려다보도록** 고정 설치
  - `hand_cam`: 엔드이펙터 부근에 부착 (eye-in-hand)
  - 로봇 크기는 약 900 × 700 mm이고, 팔의 주 작업 공간은 로봇 **오른쪽**입니다.

### 1.2 최종 목표
- `front_cam`이 보는 태그 B와 `hand_cam`이 보는 태그 A 사이의 상대자세 ${}^{A}T_{B}$를 로봇이 **얼마나 정확히 계산하는지 정량화**합니다.
- 오차를 **보정값으로 부여**합니다.

### 1.3 이전 논의에서 확정된 설계 판단 (이유 포함)

1. **보정값은 최종 결과(${}^{A}T_{B}$)에 상수로 더하지 않습니다.**
   오차는 팔 자세 $q$와 베이스 위치에 따라 달라집니다. 결과에 더한 상수 보정은 데이터를 수집한 자세에서만 맞습니다.
2. **보정값은 변환 체인 안의 고정 강체 변환에 적용합니다.** 대상은 $X={}^{b}T_{fc}$와 $Y={}^{ee}T_{hc}$이며, 이렇게 해야 새로운 자세와 위치로 일반화됩니다.
3. 오차는 **bias(평균)와 random(표준편차)으로 분리**해서 봅니다. 보정으로 줄일 수 있는 것은 bias뿐입니다.
4. 외부 파라미터를 보정한 뒤에도 남는 bias는 상관 분석으로 원인을 구분합니다.
   - $q$에 의존하면 → 팔 기구학(FK) 오차
   - 거리·시야각에 의존하면 → 검출 또는 intrinsic 오차
5. **팔을 터치 프로브로 써서 GT를 만들지 않습니다.** 검증 대상인 FK 오차가 GT에 섞이는 순환논리가 되기 때문입니다.
6. 사용자 전제:
   - 시트 평탄도·변형은 **고려하지 않음**
   - front_cam은 수직 하향이라 원근 왜곡 걱정은 **적음**
   - 인쇄 치수는 **인쇄 후 사용자가 실측**
7. 회전 오차는 거리만큼 증폭됩니다. 1°는 1 m에서 약 17 mm입니다. 따라서 **회전 성분의 정확도가 핵심**입니다.

## 3. 좌표계와 표기 규약 (가장 중요)

### 3.1 변환 표기
- ${}^{a}T_{b}\in SE(3)$ = "**a 좌표계에서 본 b의 자세**"
- 점 변환: $p_a = {}^{a}T_{b}\,p_b$
- 합성: ${}^{a}T_{c} = {}^{a}T_{b}\,{}^{b}T_{c}$
- 역: ${}^{b}T_{a} = ({}^{a}T_{b})^{-1}$
- 코드 변수명 규칙 권장: `T_a_b` (= ${}^{a}T_{b}$)
- **단위**: 내부 계산은 **m**와 rad로 통일합니다. JSON은 mm이므로 로드할 때 변환합니다.

### 3.2 좌표계 목록

| 기호 | 이름 | 설명 |
|---|---|---|
| $W$ | world / sheet | **tag 200 좌표계**. 원점 = tag 200 중심 |
| $k$ | tag k | 시트 위 각 태그 좌표계 |
| $b$ | arm base | 매니퓰레이터 베이스 링크. 모바일 베이스에 강체 고정 |
| $ee$ | end-effector | FK가 주는 플랜지 또는 tool 프레임 (예: `tool0`, `wrist3_link`) |
| $fc$ | front_cam **optical** frame | x 오른쪽, y 아래, z 광축 전방 (REP-103 optical) |
| $hc$ | hand_cam **optical** frame | 위와 동일 |

> ⚠️ **optical frame과 camera_link를 혼동하지 마세요.** 태그 검출·PnP 결과는 항상 optical frame 기준입니다. ROS의 `*_camera_link`(x 전방)와 `*_optical_frame` 사이에는 고정 회전이 있습니다. URDF에 반영할 때 이 회전을 합성해야 합니다(10장).

### 3.3 태그·시트 좌표계 규약 (AprilTag 3 규약, 실험으로 검증됨)
- 원점: 태그 중심
- $+x$: 인쇄물을 정방향으로 볼 때 **오른쪽**
- $+y$: 인쇄물 기준 **아래쪽**
- $+z$: **종이 속**. 시트를 바닥에 깔면 **지면 아래 방향**이며, 사용자가 말한 "z축이 지면 아래를 향함"과 일치합니다.
- 시트 위 모든 태그는 **같은 평면, 같은 방향**입니다. 따라서 ${}^{W}R_{k}=I$이고 ${}^{W}t_{k}=(x_k, y_k, 0)$입니다.

> ⚠️ OpenCV ArUco 계열 규약(y 위, z 태그 밖)과는 **x축 기준 180° 회전** 차이가 납니다. 5장의 코너 순서 표를 따라 **직접 3D 점을 대응**시키면 규약 문제를 피할 수 있습니다.

### 4.4 인쇄 후 실측 반영 (필수)
PDF 자체의 오차는 0.001 mm 미만입니다. 실제 오차는 **플로터 급지 방향 스케일(0.1~0.3%)과 용지**에서 생깁니다. 코드는 설계 JSON을 그대로 쓰지 말고, 실측값으로 덮어써야 합니다.

**측정 항목**
- 가로 스케일 $s_x$: 200–301 중심 간 1000 mm와 300–301 150 mm를 강철자로 측정
- 세로 스케일 $s_y$: 300–308, 301–309 600 mm를 측정
- 태그 한 변: 5개 이상을 캘리퍼스로 재서 평균 → `tag_size_measured`

**반영 방법**
$$
{}^{W}t_k^{\text{meas}} = (s_x\,x_k,\; s_y\,y_k,\; 0),\qquad s = \text{tag\_size\_measured}
$$

- 설정 파일 예: `sheet_scale: {sx: 1.0000, sy: 1.0000, tag_size_m: 0.0900}`
- 태그 크기가 1% 틀리면 1 m 거리에서 깊이가 약 10 mm 틀어집니다. 이 오차는 외부 파라미터 bias와 구분되지 않으므로 반드시 실측값을 넣으세요.

## 5. 태그 검출 규약 (실험으로 검증한 사실)

시트 PDF를 래스터화한 뒤, 가상 핀홀 카메라(영상 x = 종이 오른쪽, y = 종이 아래, 광축 = 종이 속)로 검출해서 확인했습니다.

### 5.1 `pupil_apriltags` (AprilTag 3 Python 바인딩)
- 이 가상 카메라 배치에서 `pose_R ≈ I`가 나옵니다. 즉 태그 프레임은 3.3절 규약과 **일치**합니다.
- `pose_t`도 tag 200 위치와 일치했습니다(수 mm 이내, 래스터 해상도 수준).
- `corners[i]`에 대응하는 **태그 프레임 3D 점**($s$ = tag size):

| index | 인쇄물 위치 | 태그 프레임 좌표 |
|---|---|---|
| 0 | 좌하 | $(-s/2,\;+s/2,\;0)$ |
| 1 | 우하 | $(+s/2,\;+s/2,\;0)$ |
| 2 | 우상 | $(+s/2,\;-s/2,\;0)$ |
| 3 | 좌상 | $(-s/2,\;-s/2,\;0)$ |

### 5.2 OpenCV `cv2.aruco` + `DICT_APRILTAG_36h11`

| index | 인쇄물 위치 | 태그 프레임 좌표 (3.3 규약) |
|---|---|---|
| 0 | 우하 | $(+s/2,\;+s/2,\;0)$ |
| 1 | 좌하 | $(-s/2,\;+s/2,\;0)$ |
| 2 | 좌상 | $(-s/2,\;-s/2,\;0)$ |
| 3 | 우상 | $(+s/2,\;-s/2,\;0)$ |

→ pupil_apriltags와 **인덱스가 2칸 밀려 있습니다.** OpenCV `estimatePoseSingleMarkers`나 IPPE_SQUARE 기본 규약이 주는 포즈는 3.3 규약과 다르므로 **사용하지 마세요.**

### 5.3 권장 사용 방식
- 검출기가 주는 태그별 포즈를 쓰지 않습니다.
- 대신 **검출된 모든 태그의 코너 픽셀 ↔ 시트 W 좌표 3D 점**을 한꺼번에 PnP에 넣어 ${}^{cam}T_{W}$를 직접 구합니다(multi-tag PnP).
  - 3D 점: ${}^{W}p = {}^{W}t_k + (\pm s/2, \pm s/2, 0)$, 부호는 위 표를 따름
  - 초기값: 가장 큰 태그 1개로 `SOLVEPNP_IPPE`(평면) → 전체 점으로 `SOLVEPNP_ITERATIVE` 또는 LM refine
- **단위 테스트로 반드시 재검증합니다.** `tests/test_corner_convention.py`에서 FINAL2 PDF를 래스터화하고, 위와 같은 가상 카메라로 multi-tag PnP를 수행해 $R\approx I$, $t\approx$ 알려진 값인지 확인합니다. 검출기 버전이 바뀌면 순서가 달라질 수 있습니다.
- 평면 PnP의 **flip 모호성**이 있습니다. 태그 1개만 보일 때는 IPPE의 두 해 중 재투영 오차가 작은 해를 고르고, 비율이 1.2 미만으로 애매하면 샘플을 폐기합니다. 태그가 여러 개 보이면 대부분 해소됩니다.

## 6. 문제 정식화

### 6.1 측정 가능한 것과 미지수

샘플 $i$ (로봇 정지 상태, 두 카메라 영상과 관절값을 동시에 획득):

| 기호 | 정의 | 출처 |
|---|---|---|
| $F_i = {}^{b}T_{ee}(q_i)$ | FK | 로봇 컨트롤러 또는 TF (`b → ee`) |
| $P_i = {}^{fc}T_{W}$ | front_cam이 본 시트 | multi-tag PnP |
| $Q_i = {}^{hc}T_{W}$ | hand_cam이 본 시트 | multi-tag PnP |
| $X = {}^{b}T_{fc}$ | **미지수** (전면카메라 외부 파라미터) | 초기값 $X_0$ = URDF/TF 공칭값 |
| $Y = {}^{ee}T_{hc}$ | **미지수** (hand-eye) | 초기값 $Y_0$ = URDF/TF 공칭값 |
| $Z_j = {}^{b}T_{W}$ | 베이스 스테이션 $j$에서 베이스와 시트의 관계 | 부수 미지수 (BA에서만 사용) |

두 카메라는 **서로 다른 태그를 봐도 됩니다.** 시트 전체가 하나의 강체 좌표계 $W$로 묶여 있기 때문에, 각 카메라는 보이는 태그만으로 ${}^{cam}T_W$를 구하면 됩니다.

### 6.2 닫힌 루프
베이스와 시트가 샘플 동안 움직이지 않으면 다음이 성립합니다.
$$
{}^{b}T_{W} \;=\; X\,P_i \;=\; F_i\,Y\,Q_i
$$

### 6.3 순간 hand_cam → front_cam 변환 (측정 vs 공칭)
$$
{}^{fc}T_{hc}^{\,\text{meas},i} = P_i\,Q_i^{-1},\qquad
{}^{fc}T_{hc}^{\,\text{nom},i} = X_0^{-1}\,F_i\,Y_0
$$

오차는 다음과 같이 정의합니다.
$$
E_i = \big({}^{fc}T_{hc}^{\,\text{nom},i}\big)^{-1}\,{}^{fc}T_{hc}^{\,\text{meas},i},\qquad
e_{t,i}=\|t(E_i)\|,\quad e_{R,i}=\arccos\!\Big(\tfrac{\mathrm{tr}\,R(E_i)-1}{2}\Big)
$$

- 이 값이 **"보정 전 오차"** 입니다. 사용자가 원래 알고 싶어 한 양입니다.
- 이 자세 의존 변환 자체는 보정 대상이 아니고, 평가 지표입니다.

### 6.4 AX = YB 형태
6.2를 정리하면 다음과 같습니다.
$$
\underbrace{F_i^{-1}}_{A_i}\,X \;=\; Y\,\underbrace{Q_i\,P_i^{-1}}_{B_i}
$$

검산: $A_iX = {}^{ee}T_{b}\,{}^{b}T_{fc} = {}^{ee}T_{fc}$, $\;YB_i = {}^{ee}T_{hc}\,{}^{hc}T_{fc} = {}^{ee}T_{fc}$ ✓

이것은 robot-world/hand-eye 동시 캘리브레이션 형태입니다(Dornaika–Horaud, Shah 2013, Li 2010 등).

> OpenCV `cv2.calibrateRobotWorldHandEye`를 초기값으로 쓸 수 있습니다. 다만 입력의 방향 정의(world2cam, base2gripper 등)가 위 식과 다르게 되어 있으므로, **문서를 확인한 뒤 7.4의 합성 데이터 테스트로 매핑을 검증**하고 쓰세요. 공칭 URDF 값이 수 cm, 수 도 이내로 맞으면 초기값은 공칭값으로 충분합니다.

### 6.5 추정 모드

| 모드 | 가정 | 해법 |
|---|---|---|
| `Y_fixed` | hand-eye를 신뢰 | $X_i = F_i\,Y_0\,Q_i\,P_i^{-1}$를 샘플마다 계산 → SE(3) 평균 |
| `X_fixed` | 전면카메라 장착값을 신뢰 | $Y_i = F_i^{-1}\,X_0\,P_i\,Q_i^{-1}$ → SE(3) 평균 |
| `XY` (기본 권장) | 둘 다 추정 | 6.6의 비선형 최소제곱 → (선택) 6.7 BA |

SE(3) 평균은 이동은 산술평균으로, 회전은 쿼터니언 평균(Markley 고유벡터법)이나 Karcher 평균($\log$ 반복)으로 구합니다. 평균과 함께 **분산도 반드시 출력**합니다.

### 6.6 1단계: SE(3) 잔차 최소제곱
$$
\min_{X,Y}\sum_i \rho\Big(\big\| W\,\log^\vee\!\big((X P_i)^{-1} F_i\, Y\, Q_i\big)\big\|^2\Big)
$$

- 파라미터화: $X = X_{\text{init}}\exp(\hat\xi_X)$, $Y = Y_{\text{init}}\exp(\hat\xi_Y)$ ($\xi\in\mathbb{R}^6$)
- 가중치 $W$: 회전과 이동의 단위를 맞춥니다. 예: 회전[rad] × 특성거리(0.5~1 m)
- $\rho$: Huber 또는 Cauchy (이상치 대비)
- 도구: `scipy.optimize.least_squares` (구현 쉬움). 필요하면 GTSAM이나 Ceres

### 6.7 2단계 (권장): 재투영 기반 번들 조정
PnP 결과 대신 **코너 픽셀**을 직접 관측으로 씁니다. 단일 태그 PnP의 약한 깊이·기울기 추정 문제를 완화할 수 있어 가장 정확합니다.

- 미지수: $X,\;Y,\;\{Z_j\}$ (베이스 스테이션마다 하나)
- front_cam 관측: $u = \pi\big(K_{fc}, D_{fc};\; X^{-1} Z_j\; {}^{W}p\big)$
- hand_cam 관측: $u = \pi\big(K_{hc}, D_{hc};\; Y^{-1} F_i^{-1} Z_j\; {}^{W}p\big)$
- 잔차: 픽셀 단위, Huber
- 초기값: 1단계 결과, $Z_j$는 스테이션 내 $X P_i$ 평균
- 식별성: $F_i$의 회전이 다양하면 $Y$와 $Z_j$가 결정되고, front_cam 관측으로 $X$가 결정됩니다. 게이지 자유도는 없습니다.
- (선택) intrinsic은 고정합니다. 풀어버리면 외부 파라미터와 상관이 커집니다.
- (선택, 후순위) 관절 오프셋 $\delta q$를 추가해 기구학 보정까지 할 수 있습니다. 10장 이후 과제입니다.

### 6.8 관측성 조건 (데이터 설계 근거)
- $Y$(hand-eye) 식별에는 **ee 회전 사이에 서로 평행하지 않은 회전축이 최소 2개** 필요합니다. 실무 기준으로 **20~30 자세 이상, 회전 변화 ≥ 30°, 3축 모두**를 확보합니다.
- 순수 평행이동만 있거나 한 축 회전만 있으면 $Y$의 일부 성분이 결정되지 않습니다.
- 베이스 스테이션을 2~4곳으로 바꾸면 $X$와 $Z$의 분리가 좋아지고, **스테이션 단위 교차검증**이 가능해집니다.

## 7. 데이터 수집 절차

### 7.1 준비
1. 시트를 바닥에 고정하고 4.4절 실측을 합니다.
2. 두 카메라 intrinsic을 확인합니다. `camera_info`의 K, D, 왜곡 모델을 사용합니다.
   - **raw 영상 + D** 조합을 쓰든 **rect 영상 + P, D=0** 조합을 쓰든, 한 가지로 일관되게 씁니다.
3. 노출과 초점을 고정합니다. 자동노출·자동초점은 끕니다.
4. 공칭 $X_0, Y_0$를 TF에서 스냅샷으로 저장합니다(`b → fc_optical`, `ee → hc_optical`).

### 7.2 샘플 설계
- **스테이션** $j$ = 로봇 베이스를 시트 기준으로 한 위치에 정지시킨 상태입니다.
  - 각 스테이션에서 front_cam 시야에 **시트 태그가 1개 이상**(가능하면 2개 이상) 보여야 합니다.
- 각 스테이션에서 팔 자세 20~30개를 잡습니다.
  - hand_cam이 태그 **2개 이상**을 보도록 합니다(300번대 격자 활용).
  - 카메라–태그 거리와 시야각을 다양하게 합니다. 실제 작업 거리를 포함해야 합니다.
  - 회전 다양성은 6.8절 기준을 따릅니다.
  - 관절 한계나 특이점 근처 자세는 피합니다.
- 총 샘플의 **20~30%(가능하면 한 스테이션 전체)는 검증용**으로 따로 둡니다.

### 7.3 캡처 프로토콜 (샘플 1개)
1. 팔 이동 → **정지 판정**: 관절 속도 ≈ 0 상태가 1초 이상 유지되고, 베이스 odom 속도가 0
2. 두 카메라에서 각각 **K = 10프레임** 획득. 같은 시간 창의 `joint_states`와 TF(`b → ee`)도 함께 저장
3. 프레임별 검출 → 태그별 코너의 **중앙값**을 계산. 코너 표준편차가 0.3 px를 넘으면 경고
4. 품질 필터
   - `hamming == 0`
   - `decision_margin`이 임계값 이상
   - 코너가 영상 가장자리 여백(예: 10 px) 안쪽
   - 태그 한 변 픽셀 길이가 최소값 이상
5. 원본 영상도 저장합니다. 오프라인에서 재처리할 수 있어야 합니다.

## 9. 검증·평가

### 9.1 지표
- 순간 ${}^{fc}T_{hc}$ 오차 $e_t$ [mm], $e_R$ [deg]: **보정 전 / 보정 후 / 검증셋**
  - 각각 평균, 표준편차, RMS, 95퍼센타일
- 루프 잔차: $\log\big((XP_i)^{-1}F_iYQ_i\big)$의 성분별 분포
- 재투영 RMS [px]: 카메라별, 보정 전후
- 원래 목표 지표: 태그 쌍 (A∈hand_cam 시야, B∈front_cam 시야)에 대해
  $$
  {}^{A}T_{B}^{\text{est}} = ({}^{hc}T_{A})^{-1}\,Y^{-1}F_i^{-1}\,X\,{}^{fc}T_{B}
  $$
  이 값과 시트 GT ${}^{A}T_{B}^{gt} = ({}^{W}T_{A})^{-1}\,{}^{W}T_{B}$를 비교합니다.

### 9.2 원인 진단 (잔차 상관 분석)

| 잔차가 상관되는 변수 | 의심 원인 | 조치 |
|---|---|---|
| 없음 (일정한 bias) | 외부 파라미터 | X, Y 보정으로 해소되어야 함 |
| 관절값 $q_k$ | FK 오차 (관절 오프셋, 링크 길이, 처짐) | 기구학 캘리브레이션 검토 |
| 카메라–태그 거리, 시야각 | 검출 또는 intrinsic, 태그 크기 오차 | intrinsic 재보정, tag size 실측 재확인 |
| 스테이션 | 시트나 베이스가 움직임, 스케일 오차 | 시트 고정 확인, $s_x, s_y$ 재측정 |

### 9.3 합격 기준 (예시, 사용자와 확정 필요)
- 검증셋 순간 ${}^{fc}T_{hc}$ 오차: 평균 $e_t$ < 2 mm, $e_R$ < 0.2°
- 재투영 RMS < 0.5 px
- 검증셋 오차가 학습셋 대비 1.5배 이내 (과적합 아님)

## 10. 보정값 적용

1. 결과 $X^* = {}^{b}T_{fc\_optical}$, $Y^* = {}^{ee}T_{hc\_optical}$
2. **URDF 조인트가 optical frame을 직접 정의하지 않는 경우**가 대부분이므로 합성이 필요합니다.
   $$
   {}^{parent}T_{cam\_link}^{\text{new}} = {}^{parent}T_{b}\;X^*\;\big({}^{cam\_link}T_{optical}\big)^{-1}
   $$
   hand_cam도 같은 방식입니다. $ee$가 URDF 조인트의 parent 링크와 다르면 그 사이의 고정 변환을 합성합니다.
3. URDF `<origin xyz rpy>`의 rpy는 **고정축 roll→pitch→yaw** 입니다. 즉 $R = R_z(y)\,R_y(p)\,R_x(r)$입니다. 변환 후 다시 행렬로 바꿔 원래 $T$와 일치하는지 assert합니다.
4. 산출물
   - URDF 조각
   - `static_transform_publisher`용 파라미터 (ROS2: `--x --y --z --qx --qy --qz --qw --frame-id --child-frame-id`)
   - 보정 전후 비교표
5. (선택) Isaac Sim/Lab의 카메라 prim 포즈에도 같은 값을 반영해 sim-to-real 일관성을 유지합니다.

## 13. 미확정 사항 (작업 시작 시 사용자에게 확인)

1. **태그 역할과 로봇 배치**: 로봇이 시트 위에 올라가는지, 시트 옆에 서는지. 각 스테이션에서 front_cam과 hand_cam이 어느 태그를 보게 되는지. 로봇(900×700 mm)이 A0 시트 대부분을 가릴 수 있으므로 시야 확보 여부도 확인
2. **8 cm 높이 태그 A 구성의 유지 여부**: 이전 논의에서는 A를 B보다 약 8 cm 높은 받침대에 두는 안이 있었습니다. 받침대를 쓰면 해당 태그는 시트 평면($z_W=0$)이 아닙니다.
   - $W$의 $+z$가 지면 아래이므로, 받침대 위 태그는 **$z_W \approx -80$ mm** 입니다.
   - 받침대의 기울기와 yaw 정렬 오차가 거리만큼 증폭됩니다(0.1° → 1 m에서 1.7 mm). 경사계와 기준 태그 사진측량으로 ${}^{W}T_{A}$를 따로 측정해야 합니다.

## 부록 A. SE(3) 공식

- $\log: SO(3)\to\mathbb{R}^3$
  - $\theta=\arccos\big((\mathrm{tr}R-1)/2\big)$, $\omega = \dfrac{\theta}{2\sin\theta}(R-R^\top)^\vee$
  - $\theta\to 0$일 때 1차 근사, $\theta\to\pi$일 때 대각 성분으로 축 추출
- $SE(3)$ $\log$: $\xi=(\rho,\omega)$, $\rho = V^{-1}t$
  - $V = I + \dfrac{1-\cos\theta}{\theta^2}\hat\omega + \dfrac{\theta-\sin\theta}{\theta^3}\hat\omega^2$
- 회전 오차각: $e_R = \|\log(R_1^\top R_2)\|$
- 쿼터니언 평균: $M=\sum_i w_i q_i q_i^\top$의 최대 고유벡터 (부호 정렬 불필요)
