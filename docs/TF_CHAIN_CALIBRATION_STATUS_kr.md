# TF 체인 구조와 캘리브레이션 현황 (2026-09-22 저녁 기준)

이 문서는 **어떤 변환이 어디에 있고, 어떻게 측정됐고, 얼마나 믿을 수 있는지**를
한 곳에 모은 것이다. 적용값의 원본은 `src/apriltag_nav/config/tf/tf_chain.yaml`
(+ `arm_joint_offsets.yaml`) 하나이고, `python3 src/apriltag_nav/tools/tf_chain_tool.py
show` 가 지금 값을 출력한다. 각 항목의 근거와 날짜별 이력은 CLAUDE.md Work Log.

## 1. 체인의 구조

### 1.1 프레임

| 기호 | 프레임 | 정의 |
|---|---|---|
| **W** | 월드 | 셀 좌표 (`map.yaml`; 원점 정반 1 중심) |
| **mb** | 모바일 베이스 | x 전진, y 좌, z 위. 원점은 샤시 중심 아래 바닥. `/robot_pose` 가 기준하는 프레임 |
| **fc** | front_cam | Orbbec Femto Bolt 광학 프레임 (실제 카메라, 1.44° 기울어짐). 검출은 **수평 가상 카메라(fc_level)** 로 재투영되어 나온다 |
| **ab** | 팔 베이스 | Fairino FR10v6 base_link |
| **ee** | 플랜지 | `/arm/state` 가 보고하는 것 (컨트롤러 활성 툴 = 플랜지) |
| **hc** | hand_cam | RealSense D435 컬러 광학 프레임 (x 화면 우, y 화면 하, z 광축) |
| **tip** | 비전 팁 | Basler 프레임 중심이 Keyence standoff 에서 보는 점, 플랜지 프레임 기준 |
| **A / B** | 태그 | A = hand_cam 이 보는 기준(cross) 태그, B = front_cam 이 보는 바닥 경로 태그 |

표기: `T_X2Y` = X 프레임에서 본 Y 의 자세 (Y 점 p → X: `T_X2Y @ p`).

### 1.2 두 가지 체인

**맵 캘리브레이션 체인 (T_A2B)** — 바닥 태그의 월드 좌표를 정반의 기준 태그로부터 측정:

```
T_A2B = T_A2hc · T_hc2ee · T_ee2ab · T_ab2mb · T_mb2fc_level · T_fc2B
        └ hand_cam  └ hand-eye └ 팔 FK(live) └ 마운트  └ front_cam 자세  └ front_cam
          관측(PnP)              +관절offset                                 관측(PnP)
T_B_world = T_A_world · T_A2B
```

**포즈 모드 스캔 체인** — CSV 의 월드 좌표를 팔 목표로:

```
p_ab = inv(T_ab2mb + lift) · inv(T_W2mb from /robot_pose) · p_W    → tip → flange (T_ee2tip) → IK
```

고정 변환 네 개(`T_ab2mb`, `T_mb2fc`, `T_hc2ee`, `T_ee2tip`)와 관절 영점 offset
하나가 파일에 있고, `T_ab2ee` 는 `/arm/state` 의 라이브 값, 리프트 높이는
`/lifter/height` 를 매 소비자가 더한다 (`T_ab2mb` 는 리프트 원점에서 측정).

ROS `/tf` 로는 이 체인이 존재하지 않는다 — navifra 의 `odom→base_link` 와 각
카메라 드라이버의 고립된 서브트리뿐이고, 실제 체인은 위 설정 행렬을 코드가 읽는다.

## 3. 오차 요소별: 무엇을, 어떻게, 얼마나

T_A2B 에 오차를 넣을 수 있는 요소를 체인 순서대로. 각 항목은 **방법 → 결과 → 정확도
→ 개선 → 남은 것**.

### 3.1 hand_cam 내부 파라미터 (K, D) — 체인의 맨 앞

- **문제:** D435 드라이버는 D = 0, fx 609.3 을 보고한다. 실제 렌즈는 왜곡이 있고
  (구석에서 7 px) fx 는 1.2 % 낮다. 1 % 의 fx 는 0.45 m 에서 4.5 mm 의 깊이 오차이고,
  hand-eye z 와 축퇴한다.
- **1차 (09-21):** A0 시트 코너 60뷰로 `calibrateCamera` → fx 601.7 / fy 603.9, k1 +0.160.
  한 거리(0.45 m), 화면 중앙 위주 → k1 과 fx, hand-eye z 가 서로 흡수. fy/fx = 1.0036
  은 A0 인쇄물의 y 스케일 오차가 카메라로 새어 들어간 것이었다.
- **2차 (09-22, 적용):** 11×8 체커보드(14.99 mm 실측) 67뷰, 0.19–0.56 m 세 거리,
  기울기 52° 까지, 구석 10장. `tools/hand_cam_intrinsics.py`. rms 0.41 px.
  - 홀/짝 절반: fx 0.9 px, k1 0.0006 일치. 3-fold hold-out: 새 값 0.412 px, 09-21 값
    0.441, 드라이버 0.676.
  - near/far 절반은 fx 4.4 px 벌어짐 — 각 절반이 거리 다양성을 잃어 fx–k1 축퇴 골짜기에
    앉기 때문(far 절반 fx sd 1.57 px). 판정은 hold-out 으로.
  - **fy = fx** (601.9 / 601.9). 인쇄물 스케일이 카메라에 섞이지 않는 타깃이라 그렇다.
- **개선:** 독립 데이터(팔 세션)의 반경 방향 잔차 추세 드라이버 −4.0 → 09-21 −1.7 →
  **−1.05 px**. hand-eye 재해석에서 태그 산포 2.66 → 2.06 mm.
- **적용 방식:** `robot_camera_node` 가 hand_cam 프레임을 (K, D) 로 리매핑해 검출 →
  `/hand_cam/tag_detections` 는 왜곡 없는 프레임, 소비자는 (K, D=0). 드라이버
  `/hand_cam/color/image_raw` 는 그대로 raw.
- **남은 것:** 팔 세션에 ~1 px 의 반경 추세가 어떤 K 로도 남는다 (AprilTag 코너 검출기의
  편향 또는 A0 인쇄물). 원거리(0.5–0.6 m) 5장, BR 구석 1장으로 최소치.

### 3.2 front_cam 자세 (T_mb2fc) — 카메라 기울기, 레버, yaw, 태그 두께

- **왜 중요:** 기울기 1.3° 가 태그 edge 각을 위치에 비례해 돌린다(0.2 m 앞에서 +0.67°).
  0.55–0.75 m 레버를 곱하면 주행 정지의 ±10 mm 편향이 됐고, "얼라인됐다"는 정지가
  실제로는 0.2–0.5° 틀어져 있었다. 체인에서는 `T_fc2B` 의 회전이 B 의 yaw 에 1:1 로
  들어간다 (위치에는 0).
- **방법 (09-08, 09-15 `tools/calib_front_cam_pose.py`):** 정밀하게 놓은 90 mm 태그
  쌍(0.120 m 간격)을 자로 삼고, 베이스의 움직임은 **자극으로만** 쓴다 (베이스는 작은
  명령을 45 %, 피벗을 25 % 덜 실행한다 — 명령값은 절대 쓰지 않는다). 30프레임 스냅샷
  17장 → roll / pitch / 높이 피팅; 폐루프 ±6° 피벗 9장 → 회전 중심(레버, ty); 직진
  트랙 8개 → yaw.
- **결과:** roll +1.406°, pitch −0.323°, 렌즈 높이 302.0 mm (rms 0.24 px); 레버
  0.5504 m (jackknife 1.3 mm) → `camera_offset` 0.55 유지; ty +1.7 ± 3.8 mm → 0 유지;
  yaw −0.31° (fwd −0.03 / rev −0.59) → 주행 검증된 −0.38 유지.
- **정확도:** roll / pitch ±0.05° (09-08 대비 0.18° 이동 = 바닥 평탄도 크기), 레버
  ±3 mm (어느 기울기를 쓰느냐에 따라 0.5504 / 0.5465), yaw ±0.3° (바닥의 1 mm 단차가
  0.145 m 트랙에서 0.4°).
- **태그 두께 (09-15):** 모든 태그는 1 mm 판. 피팅이 재는 `height_m` 은 태그 윗면
  기준이므로 tz = 0.302 + 0.001. cross 태그도 정반 윗면보다 1 mm 위 (z +0.001).
- **개선 (주행, 108 hop):** 얼라인 후 lateral +8.8 ± 1.3 / −11.6 ± 1.6 mm → **+1.9 ±
  1.7 / −3.3 ± 2.2 mm**; yaw ±0.2°; 정지 column 오차 1 mm 이내.
- **두 프레임 규칙:** 검출은 수평 가상 카메라(fc_level)에서 나오므로 체인은
  `T_mb2fc_level = T_mb2fc · T_tilted_to_level` 을 쓴다. 로더가 robot.yaml 과 안 맞는
  yaml 을 거부한다 (기울기 두 번 적용 = 바닥 태그 8 mm / 1.38°).

### 3.3 hand-eye (T_hc2ee)

- **이력:** 2026-05 파일 → 09-02 광축 180° 뒤집힘 발견(얼라인 발산) → 09-14 자동 스윕
  23뷰 (산포 2.1 mm, cross 태그 0 이 map 대비 1 / 0 / 5 mm) → **09-18 카메라 재마운트**
  → 스윕이 옛 파일로 조준하다 발산 → bootstrap(플랜지 ±10° 회전 7장으로 임시
  hand-eye) → 스윕 3회 35샘플, PARK + 태그 산포 refine → 09-22 새 K 로 저장 프레임
  재검출·재해석 (적용).
- **방법:** `handeye_calib_node` 의 자동 스윕 (cross 태그 0 을 중심으로 거리 × 기울기
  × 방위 구면 뷰, 플레이트 클리어런스 0.12 m, 재검출로만 캡처) → `calibrateHandEye`
  → 고정 태그의 재투영 산포(위치 + 법선)를 6 파라미터로 최소화.
- **정확도:** 태그 산포 2.06 mm rms (35 샘플); jackknife 2.8 / 2.2 / 1.5 mm. 그러나
  **스윕끼리는 ~10 mm** 로 재현된다 (09-18 sweep3 vs 18샘플 파일 12.6 mm, 09-21 20:09
  스윕 vs 35샘플 파일 10.1 mm) — 한 스윕 안의 산포 3 mm 는 정밀도이지 정확도가 아니다.
  09-21 밤 "20 mm z 보정" 은 정면 한 거리 뷰로는 **관측 불가능한 축**의 artefact 였고,
  올바른 K 로도 안 바뀌었다. 저장된 모든 사진으로 다시 풀어도 09-18 파일은 **~5 mm**
  안이고 이보다 나은 후보는 없다.
- **개선:** 09-02 파일 대비 45 mm / 2.3°; 새 K 로 5.4 mm / 0.22° 이동 (2.66 → 2.06 mm).
- **남은 것:** 스윕 한 번의 10 mm 재현성 — 거리 0.30 + 0.55 m, tilt ≥ 15°, spin 30–150°
  다양성을 한 스윕 안에 넣어야 줄어든다. hand-eye 의 yaw 0.1° = 체인 끝에서 ~2 mm.

### 3.4 팔 FK — 관절 영점 offset

- **왜:** 체인이 맞은 뒤에도 `sheet_path` (렌즈를 격자 태그 위 0.5 m 로 보내기) 의
  점별 오차가 ±15–20 mm 이고 손목 spin 에 따라 패턴이 바뀐다 → 강체 마운트가 아닌
  구성 의존 오차. 다만 09-22 오전 분석: 그 ±13 mm 의 대부분은 **2–3 태그 PnP 측정
  오차**이고(2태그 뷰 xy 9.8 mm, 6태그 1.8 mm), offset 이 예측하는 렌즈 변동은
  1.2–1.6 mm rms 뿐이다.
- **방법 (`chain_calib/arm_offsets.py`):** 65뷰 팔 세션(spin 30/90/150°, 거리
  0.25–0.56 m, tilt 41° 까지, 관절각 저장)에서 시트 코너의 **재투영 px** 잔차로 J2..J6
  offset + 시트 자세 6 을 최소자승. (PnP 자세 잔차는 2태그 평면 모호성 때문에 쓸 수 없다.)
- **결과 (적용, 사용자 결정 "없는 것보다는 낫다"):** J2 −0.34, J3 −0.53, J4 −0.05,
  J5 −0.13, J6 −0.50°. 재투영 7.43 → 3.39 px (hold-out 7.75 → 3.51). 체인 hold-out
  12.7 → 7.7 mm.
- **정확도:** jackknife 0.06–0.42°. 그러나 **near / far, spin 별 서브셋은 J2/J3 에서
  ±2° 로 갈린다** (기하 자체는 식별 가능 — 심은 offset 을 0.03° 로 복원 — 모델 오차 위의
  J2/J3/시트자세 바꿔치기). 평균값이다.
- **적용 범위:** 측정 체인 (`tf_chain.arm_flange_T`: `T_ab2ee = FK(q + dq)`) 과,
  09-28 밤부터는 팔 명령 쪽도 xy 성분만 (`arm_node ~apply_joint_offsets_cmd` true,
  `~joint_offsets_cmd_skip_z` true — 팁 투어 rms 10.8 → 4.2 mm). `enabled: false`
  로 끌 수 있다.

### 3.5 팔 마운트 (T_ab2mb) — 마운트 기울기와 샤시 기울기의 분리

- **설계:** Rz(180°) 정확, t (0, −0.100, −0.652). 09-08 실로봇 655점 피팅에서 기울기
  0.0001 / 0.0007 rad → 마운트 기울기 없음.
- **1차 (09-21, 6-DOF, 63뷰 체인 세션):** t (−7.47, −123.68, −628.44), rpy (0.32,

  front_cam 이 보는 태그 200 한 장의 면외 기울기 = 그 자리 종이의 국소 경사이고,
  시트를 다시 깔자 1.7° 바뀌었다. 정반에서 내려갔다 다시 주차하자 격자 법선 vs 팔 z 도
  0.17° → 0.86° 로 바뀌었다 → **roll / pitch 는 마운트 + 그 주차의 샤시 자세 + 종이
  경사이지 로봇 상수가 아니다** (±1°, 0.64 m 레버에서 ±10 mm 의 tz/tx). yaw (1.43

- **2차 (09-22 오후, 6-DOF + 관절 offset, 팔 세션):** t (−8.68, −103.42, −643.10),

- **3차 (09-22 저녁, 적용) — 평면 피팅 규칙 (사용자):** 맵 캘리브레이션은 다른 주차

  피팅, roll = pitch = 0, tz = 설계 −0.652 고정.** t (−8.20, −106.13, −652.00),
  yaw 179.196°, jackknife 0.4 / 0.4 mm / 0.01°. 세션 rms 12.5 mm (6-DOF 7.9) — 흡수를
  거부한 ~0.5° 의 세션 기울기가 잔차로 남는 것이 의도.
- **정확도:** 로봇 상수인 yaw / xy 는 두 독립 세션이 0.1° / 2 mm 로 일치.
- **개선 (맵 캘리브레이션, 09-22 태그 123–125):** 옛 체인 → 새 체인으로 태그가 8–23
  mm (x), 21–27 mm (y) 이동해 **설계 격자 (1710, −2150 / −2550 / −2950) 위로** 왔다.
  옛 체인은 y +22 mm 편향과 레인 방향 x 드리프트가 있었다.
- **네 개는 한 세트:** (K, D) → T_hc2ee → 관절 offset → T_ab2mb 순으로 의존한다.
  앞의 것이 바뀌면 뒤를 다시 푼다.

### 3.6 샤시 기울기 (주차 자세) — 상수가 아닌 것

- 정반 옆 바닥에서 로봇을 주차할 때마다 샤시가 다른 자세로 서고, 0.64 m 레버에서
  ±1° 는 ±10 mm 다. 시트 세션끼리 ~8 mm 의 상수 이동이 이것.
- **처리:** T_ab2mb 에서 빼기로 함(3.5). 결과적으로 **각 맵 캘리브레이션 세션의 결과에
  그 주차의 기울기가 남는다** — 세션 안에서는 상수, 세션 간에는 다르다. 바닥이 평평하지
  않으면 (3 mm/m 수준이 관측됨) 태그별로도 조금씩 다르다. 실측해서 보정하려면
  세션마다 샤시 자세를 재야 한다 (아직 없음).

### 3.7 비전 팁 (T_ee2tip) — 포즈 모드에만

- **방법 (09-21 `basler_tip_calib.py`):** A4 20 mm 태그 시트. hand_cam 으로 시트 자세
  (5 spin, 30태그 PnP), Basler 로 standoff 에서 태그 하나씩 10장 → 프레임 중심 아래
  시트 점 + 이미지 각 → (p_tip, ψ) 최소자승.
- **결과 (09-21 짝):** (−1.81, −245.59, 209.60) mm, 이미지 roll −179.11°. 설계 대비
  (−1.8, +7.4, −15.6) — z 는 09-18 케이스 단축, y 는 실제 7 mm.
- **재해석 (09-22 저녁, 적용값):** 같은 세션의 코너를 새 hand-eye(체커보드 K 재해석)
  + 체커보드 K 로 다시 풀면 **(−2.0, −245.2, 214.4) mm** — x −0.2, y +0.4, z +4.8.
  z 의 4.8 mm 는 hand-eye 재해석의 z 이동(−4.6 mm)이 그대로 전달된 것; xy 는 로봇
  검증(2.6 mm)의 잡음 안. `basler_tip_calib.py --hand-intrinsics config solve` 로
  재현 (`result_K20260922_HE20260922.*`). 이것으로 K → hand-eye → offset → T_ab2mb →
  tip 다섯 값이 한 세트.
- **정확도:** 피팅 5.5 mm rms 인데 잔차가 손목 spin 에 (1−cos θ) 형태로 커진다 = 팔의
  ~1° 자세 오차 × 246 mm 레버. 정직한 불확도 ±1.5 / ±3 / ±2 mm.
- **로봇 검증:** 태그 215 에 실측 팁으로 이동 → 오차 2.6 mm; 설계 팁 → 7.5 mm.
- **결과:** 플래너 export 는 설계 팁·설계 마운트·idle 정지자세로 풀려 있어 조인트
  재생과 포즈 모드가 다른 곳을 간다 — 09-29 의 `tools/retarget_joint_paths.py` 가
  조인트 파일을 실측 체인으로 재해석한다 (현재 task/csv 의 10mm 쌍은 원본, 미적용).

### 3.8 타깃 (시트, 인쇄물, 태그)

- **인쇄 스케일:** 전역 스케일은 피팅에서 관측 불가능(hand_cam 깊이와 축퇴) → 강철자
  실측이 입력 (1.0 / 1.0 / 90.00 mm). 코너가 보여 주는 **y 만 −0.35…−1 % 수축** 은
  미해결 (309 에서 −5.8 mm). 0.2 % = 1–2 mm 의 체인 오차.
- **종이 경사:** front_cam 이 보는 태그 200 이 0.3–1.0° 기울어 읽힘 → 시트를 테이프로
  고정하고 `capture` 의 paper slope < 0.5° 확인. 3.5 의 roll 문제의 원인.
- **cross 태그:** 정반의 정밀 가공 슬롯 → 위치는 가공 기하. 인쇄 정합 ±0.2 mm 는 90 mm
  에서 ±0.13° 의 yaw = 레버 끝 ~2.8 mm — 확인 안 됨.
- **태그 검출 (PnP):** 2태그 뷰의 평면 모호성 (가짜 3–7° 기울기 + 30–110 mm 깊이). 팔
  세션에서 태그 수별 렌즈 xy 오차: 2태그 9.8 mm, 4태그 8.3, 6태그 1.8 (offset 후).
  **측정은 ≥ 4 태그 뷰(0.55 m)에서** 해야 체인을 판단할 수 있다.

### 3.9 베이스 정지 자세 — T_A2B 가 아니라 T_B_world 에

- `/robot_pose` 는 map.yaml 의 태그 좌표 + lateral + camera_offset + 태그의 전후 거리로
  만든다. 태그 상대 정확도(정지 1 mm, lateral ±2 mm, yaw ±0.2°)는 좋지만 **월드 좌표는
  map.yaml 의 정확도를 그대로 물려받는다** — 그래서 맵 캘리브레이션이 필요하다.
- 세션 간 반복성 sd_xy 2.9 mm (09-11). 오차는 잡음이 아니라 계통.

### 3.10 리프트

- `T_ab2mb` 는 리프트 원점에서 측정. 포즈 모드 IK 와 locator 체인 모두 라이브
  `/lifter/height` 를 더한다 (09-11 / 09-01). 스케일 0.04976 mm/count 실측(343.2 mm
  @ 6897). 원점 복귀 후 상승으로만 도달 (백래시).

## 5. 의존 순서 — 무엇이 바뀌면 무엇을 다시 하나

```
A  hand_cam K, D  ──┬──▶ C  hand-eye T_hc2ee ──▶ D  T_ee2tip (포즈 모드만)
                    │            │
B  front_cam T_mb2fc┤            ▼
                    └──▶ E'  관절 offset ──▶ E  T_ab2mb ──▶ F  맵 캘리브레이션 ──▶ G  주행/스캔
```

- A 가 바뀌면 C 부터 전부 (09-22 에 그렇게 했다).
- B 는 A 와 독립 (다른 카메라). 재마운트 시 `calib_front_cam_pose.py` → `tf_chain_tool.py
  front-cam --apply`.
- C 는 hand_cam 재마운트마다. E' 와 E 는 C 에 고정되어 피팅됐으니 C 가 바뀌면 둘 다.
- F 의 결과(`map_world_*.yaml`)는 그 시점의 체인 것 — **체인이 바뀐 뒤의 F 만 유효**.
  09-22 16:16 이전의 오늘 세션은 옛 체인.
- 파일 갱신 후 재시작: `arm_node` (T_ab2mb, T_ee2tip), 캘리브레이션 launch 4노드,
  `robot_camera_node` (K, D, ground_plane).

검사 스크립트: `tf_chain_tool.py check` 13, `check_pose_vs_joint` 27,
`check_lift_compensation` 11, `check_joint_offsets` 22, `check_front_cam_extrinsics` 24,
`check_camera_intrinsics_override` 20, `check_chain_calib` 48, `check_basler_tip` 11.
